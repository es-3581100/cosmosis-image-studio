00 / SYSTEM

What this workstation is

Cosmosis Image Studio treats images, masks, prompts, references, versions and projects as primary objects. Providers are routed beneath the editing workflow. Originals are immutable; every generation or transformation becomes a child asset and lineage node.

01 / WORKSPACE

Workspace map

OPENRNDR owns the instrument field: image rendering, technical grid, zoom/pan, registration corners, mask overlay, version strip and worker status. Native desktop controls own text-heavy prompt editing, provider settings, file dialogs and the mask-edit dialog.

02 / STORAGE

Projects and recovery

Project metadata lives in SQLite; image bytes live in filesystem asset folders. On restart, persisted RUNNING jobs become INTERRUPTED. They are shown for inspection instead of being automatically retried.

03 / PROMPTS

Prompt tree contract

MY PROMPTS are editable. PREMADE PROMPTS are read-only upstream assets. Copy-to-local creates a fresh ID and preserves source metadata through derivedFrom/source/sourceUrl/sourceVersion/sourceLicense. Edits create immutable prompt revisions.

04 / ANALYSIS

Image → Structure → Prompt

The baseline local analyzer derives image dimensions, orientation, luminance, edge density and palette without a network call. Structured output keeps subject, style DNA, composition, camera, lighting, color, materials, typography, quality and avoid constraints separate so the user can edit them before saving.

05 / MASKS

Non-destructive masks

Masks are independent grayscale PNG lineage objects. Brush, erase, undo, redo, clear, invert and feather operate on the mask, not the source. A separate RGBA preview overlay is used for canvas visualization.

06 / PROVIDERS

Capability routing

Canonical GenerationRequest objects are validated before a provider adapter receives them. Unsupported masks, reference counts, output formats, quality levels or dimensions fail with actionable errors. Secrets come from environment/configured secret providers and are redacted from reports.

07 / WORKERS

Bounded actor / worker engine

Director, Prompt Compiler, Visual Analyzer, Mask Worker, Provider Router, Generation Workers, Critic, Curator, Lineage Writer and Export Worker are explicit roles. Agent Build first produces a visible Director plan and requires confirmation of finite generation/retry/parallelism/timeout/spend bounds before execution. It retrieves a small indexed local knowledge packet, records the plan ID and consulted capability IDs, runs through the ordinary provider worker path, writes critic observations without deleting results, and preserves output lineage. Cancellation is terminal: provider results arriving after cancellation are discarded rather than admitted to the project.

08 / LOCAL ML

ORML boundary

This build registers U2Net, BodyPix, image classifier/embedding and super-resolution as optional local capabilities. Each has a dedicated agent page. If the required ORML runtime classes are absent, capability discovery fails closed. Native ORML inference is not claimed as verified in this build.

09 / AGENT

Runtime self-knowledge

Every agent document contains a small application/json manifest and stable section IDs. AgentIndex tokenizes intents/aliases/capability names and returns a short deterministic context packet; the runtime does not scrape the entire manual for every action.

10 / MAINTENANCE

Artifact hygiene

When adding a meaningful capability, update implementation, tests, agent index and user documentation together. Never import third-party source or prompt corpora without recording license/provenance. Never store secrets in projects or generated reports.

11 / KEYBOARD

Keyboard map

Ctrl/Cmd+K focuses the control surface; Ctrl/Cmd+Enter runs the current prompt; G/E/M switch conceptual generation/edit/mask workflows; C toggles compare mode; 0 resets fit. Prompt text controls should keep ordinary undo/redo behavior and should not lose content on new prompt without an explicit warning.

12 / VERIFICATION

Current verification state

The dependency-light core smoke harness exercises prompt revisions/provenance/exchange, branching lineage, masks, local analysis, deterministic local generation, spend estimation, capability validation, provider translation, registry migration, secret redaction, ORML registration, HTML sanitation, bounded Director planning and intent lookup. The offline dependency-resolved acceptance smoke additionally exercises SQLite, coroutine workers, local-preview generation/editing, Agent Build + critic output, restart recovery and report export. GitHub CI provisions JDK 21 + Gradle 9.8.0 to run these network-free tests; live provider calls remain explicitly opt-in and require credentials.
