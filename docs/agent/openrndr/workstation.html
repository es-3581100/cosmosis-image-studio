Authority

The build reference organizes OPENRNDR by concepts rather than repositories. Cosmosis follows the same approach: editor intent selects an internal capability; repository/module details stay below the user workflow.

Drawing and rendering

ReferenceCosmosis use
openrndr-draw, openrndr-filterNative canvas, image presentation, registration markers and technical overlays.
orx-image-fitReference pattern for fit/contain behavior; current implementation keeps a small explicit fit calculation rather than adding a dependency solely for one operation.
orx-fx, orx-compositorExtension points for future GPU effect/composite pipelines. They are not claimed as active until a concrete editor feature needs them and tests cover it.

Interaction and parameters

openrndr-event, orx-parameters and the interaction guide informed the separation between canvas input and ordinary Swing controls. OPENRNDR owns pan, zoom, drop, workspace keys and visual instrumentation; Swing owns text entry, file pickers, trees, lists, warnings and settings.

Images and computer vision

The reference branch around orx-image-fit, orx-integral-image, orx-jumpflood and openrndr-x-boofcv is treated as an expansion map. Today Cosmosis exposes local deterministic saliency/OCR regions and optional ORML adapters as derived metadata. Analysis overlays are thin, toggleable annotations and never overwrite source pixels.

Animation and time

openrndr-animatable and ORX easing/time modules are references for future mechanical transitions. Phase-one motion remains deliberately small; the project persists reduced-motion, motion-level and density settings instead of requiring animation libraries for static editor operations.

Text, SVG and typography

orx-text-writer, orx-text-on-contour, orx-svg and orx-composition define useful future vector/text expansion points. Current text-poster workflow treats visible wording as exact user copy and provider capability, not as a silent prompt rewrite.

Shaders and GPU

openrndr-gl-common, orx-shade-styles, orx-shader-phrases and ORSL are appropriate for effects that materially benefit from GPU execution. Cosmosis does not add shader complexity merely for visual decoration.

Dependency policy

Semantic reference does not equal mandatory dependency.

Add an OPENRNDR/ORX module only when a concrete Cosmosis feature needs it, its current API/version is verified, its license/provenance is recorded, and offline tests can distinguish absence from success. This keeps the workstation model- and extension-friendly without bloating the startup/runtime surface.
