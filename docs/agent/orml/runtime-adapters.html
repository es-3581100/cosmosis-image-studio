// ORML / RUNTIME CONTRACT

Optional adapter SPI

Attach audited local-ML implementations without making ORML a mandatory Cosmosis dependency.

Purpose

Cosmosis owns the stable OrmlAdapter contract. External adapter JARs own model/runtime-specific code. The core application does not download model code during discovery.

Discovery

Adapters are discovered from the runtime classpath with Java ServiceLoader. A plugin registers one implementation class in:

META-INF/services/studio.cosmosis.orml.OrmlAdapter

Discovery does not make the adapter authoritative by itself; its capabilityId must match the curated ORML registry.

Isolated process runners

Legacy/native ORML stacks can stay outside the core JVM. Configure an executable path through one of these environment variables:

COSMOSIS_ORML_U2NET_RUNNER
COSMOSIS_ORML_BODYPIX_RUNNER
COSMOSIS_ORML_CLASSIFIER_RUNNER
COSMOSIS_ORML_SUPER_RESOLUTION_RUNNER

The executable is launched directly with no shell interpolation:

runner --capability <id> --input <absolute-file> --output <absolute-file> [--option key=value]...

The runner owns its OPENRNDR/TensorFlow/GL lifecycle. Cosmosis owns timeout, admission, output validation, project enable/disable state and lineage. A configured path that is not an executable file is rejected during discovery.

Admission checks

READY means one unambiguous adapter is installed for a known capability.

Duplicate providers are rejected rather than selected by classpath order. Class-presence probes use non-initializing class loading. File-producing adapters are accepted only when the reported output files exist.

Smart subject mask

When smart-subject-mask is READY, the studio invokes that adapter and persists its returned mask as a derived mask record. When no adapter is installed, the deterministic local saliency fallback remains available and is explicitly recorded as smart-saliency-fallback, not as ORML.

Editor semantics

smart-subject-mask becomes Smart Subject Mask, person-body-mask becomes Person Mask, image-embedding becomes derived embedding metadata, and super-resolution becomes a non-destructive UPSCALE child version. Agent Build may choose BodyPix for person/clothing intents only when ORML is enabled and that capability is READY. The project settings panel can disable all optional ORML execution without removing configuration.

Failure behavior

Never silently convert an installed-adapter failure into a claimed ORML success.

Initialization, linkage, invocation, capability mismatch, missing input, and missing output errors fail closed and appear in sanitized diagnostics.

Upstream grounding

The capability names are grounded in openrndr/orml modules including U2Net, BodyPix, image classifier, and super-resolution. Upstream implementation source is not copied here. The transport/editor integration is implemented; a specific native runner is not claimed verified until that executable and its model/runtime are tested on the target workstation.
