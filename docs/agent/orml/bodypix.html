The Cosmosis backend intentionally consumes only person-segmentation probabilities. Pose heatmaps, offsets, displacement tensors and body-part decoding are outside this capability. Ordinary CI verifies compile/package/fail-closed behavior; native inference remains pending until the manual native workflow passes.

Performance

Medium local inference. GPU can reduce latency.

Editor integration

Person selection and body-region targeting. Outputs remain derived metadata/assets.

Worker integration

Primary role: MASK.WORKER. Invocation must stay inside job budgets and be cancellable where the external runtime permits.

Common mistakes

Body-part labels are derived metadata, not identity claims. Validate segmentation before targeted edits.

Fallback behavior

If the pinned model or TensorFlow Java/native runtime is absent, the BodyPix backend fails ServiceLoader admission and the runner reports person-body-mask unavailable. Agent Build may then use the explicitly labeled local saliency fallback; it must not claim BodyPix output.

Source / provenance

Capability and graph contract are grounded in pinned openrndr/orml BodyPix source and its SHA-256-pinned MobileNet model. No ORML implementation source is copied. The backend independently implements the minimal RGB normalization, TensorFlow graph invocation, probability resize and binary person-mask threshold required by Cosmosis. See orml-runner-bodypix/runtime-manifest.json.
